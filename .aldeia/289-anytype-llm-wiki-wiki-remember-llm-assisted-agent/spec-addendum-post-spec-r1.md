# Spec Addendum — post-spec council (R1)

**Status:** Authoritative — the test phase MUST honor items 1–8 as spec requirements (write tests for them); the impl/docs phase MUST honor item 9.

## Additional acceptance criteria for the test (and impl/docs) phase

1. **[CPO-A1 + CA-A1] Supersede must leave a durable audit record.** When any `fact_actions` entry has `action="supersede"`, the superseded old text MUST be recorded in the WikiLog `notes` (the same durable audit channel used for conflicts), so a non-conflict destructive consolidation is undoable from the audit log. Add an acceptance criterion + named test asserting that a supersede action produces a WikiLog note containing the removed prior text. If implementation finds this genuinely infeasible, the alternative is to explicitly document the silent-deletion as an accepted v0.3.1 residual in spec §13 — but the default, council-preferred resolution is to record it. Do not leave it unaddressed.

2. **[CA-A2 / SF14] Surface the conflict-path provenance overwrite.** For any object flagged `wiki_status=needs-review`, EITHER record the pre-overwrite `wiki_sources` ids in the WikiLog conflict note, OR emit a `sources_overwrite_on_conflict` warning in the result dict so the overwrite is surfaced at runtime, not only in the spec. Add an AC + test for the chosen mechanism.

3. **[CSO + QA] Hard-gate and input-validation tests MUST drive the real `wiki_remember` entry point.** `test_consent_banner_fires_on_live_path` (AC-R-S1), `test_space_lock_held_returns_ingest_in_progress` (AC-R-S2), and the empty/oversize input-gate tests (AC-R25/AC-R26) MUST place the mock-spy at the `wiki_remember` call boundary. For the consent gate, assert ordering: the banner/ack check is observed BEFORE any non-local transmit. For empty/oversize, assert `space_ingest_lock`, `extract`, and `create_object` are NEVER called. A test that imports and calls an isolated helper directly DOES NOT satisfy these and MUST fail review.

4. **[CSO + QA] Assert the exact sanitized value reaches `update_object` (AC-R27 / B1).** Feed a `consolidated_text` containing a control/bidi/Unicode-tag codepoint and assert the `wiki_facts`/`wiki_definition` text in the spied `update_object` payload equals `sanitize_property_value(consolidated_text)` byte-for-byte — not merely "contains the text", "is non-empty", or "sanitize was called". The raw LLM output must be proven never to reach Anytype.

5. **[QA] AC-R6 must be twice-driven, not gate-fixtured.** `test_remember_twice_converges_no_op` MUST call `wiki_remember` twice with a stateful mock client that returns the call-1-created object on call-2 `search`. Assert: call-1 `action="created"`, call-2 `action="consolidated"`, ZERO `update_object` calls on call 2, and an identical `object_id`. The skip-gate unit tests are necessary but DO NOT substitute for this end-to-end convergence test.

6. **[QA] Conflict-flagging must be proven independent of the PATCH-skip gate (AC-R28), and the ambiguous-subject path must assert NO write (AC-R29).** (a) `test_conflict_flag_when_patch_skipped`: use an already-`needs-review` entity whose re-asserted text normalizes equal; assert the text PATCH is skipped AND `conflicts_flagged=N` + the WikiLog conflict note are still produced. (b) `test_ambiguous_subject_skips_and_warns`: spy that NO `update_object` and NO `create_object` fires for an ambiguous (>1 same-name same-type) subject, with `action="error"`/`error="ambiguous_subject"` and `status="partial"`, while a co-resident unambiguous subject still writes.

7. **[QA] Bootstrap seeding tests must assert non-empty seeding via the prop_map key-fallback path (AC-R20/R21 / B3), and follow project test conventions.** `test_bootstrap_status_tags_seed_via_prop_map_keyfallback` and its source-type sibling MUST simulate a fresh space where `list_properties` does NOT surface the inline select-property id, and assert tags are still seeded (non-zero). Additionally: every CI test MUST be fully mocked (no live Anytype/Ollama/Qdrant), live tests MUST be marked `@pytest.mark.live`, and new-surface tests MUST FAIL against the current tree before implementation begins (test-first), while the two #284 regression guards (`test_write_wikilog_default_name_is_ingest`, `test_resolve_action_tag_default_is_ingest`) MUST PASS against current source.

8. **[CTO] Add a regression assertion that `extract()` is unchanged after the `_call_ollama_prompt` refactor.** The DRY extraction of generate/chat/model-not-pulled logic touches the shipped `wiki_ingest` extraction path. Add/confirm a regression test that `extract()` produces identical request payloads (model, options, generate-then-chat fallback, model-not-pulled detection) after the helper extraction. Opportunistically fix the consent-function citation drift (§8.2 `extraction.py:276-294` vs G2 `extraction.py:261-265`).

9. **[Infra + CSO + CA] Operator-facing documentation requirements (impl/docs phase).** The v0.3.1 docs (README/CHANGELOG/upgrade note) MUST document: (a) the per-space re-bootstrap upgrade runbook (run `wiki-bootstrap --space-id <id>` per space; idempotent/union-only; clean additive rollback); (b) the auto-reindex cost model (scales with total space size, not delta) and the `WIKI_AUTO_REINDEX=false` + scheduled-batched-reindex mitigation; (c) monotonic WikiLog growth under sustained agent writes and the need for periodic pruning; (d) that `ingest_in_progress` is expected, retryable fail-fast back-pressure (the shared per-space lock does NOT block — worst-case lock-hold ≤ 8 × `WIKI_EXTRACT_TIMEOUT`); (e) that narrated `knowledge` is stored as-is (only URL credentials are scrubbed, not arbitrary secrets) and the off-machine consent banner is notify-once and non-blocking. Also confirm during impl that the existing Anytype backup is object-type-agnostic (covers the new tags/Source/WikiLog objects).

## Rationale

Items 1–2 are the council's one substantive cross-functional finding: the spec's trust posture is rigorous for conflicts (never silently overwrite) and ambiguity (never guess), but the non-conflict `supersede` path and the conflict-path `wiki_sources` overwrite are the two destructive operations with the weakest durable audit trail — flagged independently by the CPO and the Client Advocate. For a product whose entire value is "precise, well-maintained, trustworthy knowledge," making these recoverable from the audit log is the proportionate guardrail.

Items 3–8 convert the spec's existing anti-helper / anti-tautology / sanitize-on-write intent (and the two CSO impl-time conditions carried from the R2 review) into enforceable test-phase exit criteria, so the highest-stakes correctness and security properties are proven against the real entry point rather than fixtured helpers. These are not new design — they harden the status of criteria the spec already contains.

Item 9 reflects the Infra and Client-Advocate convergence that this is the first write path driven repeatedly by autonomous agents; its operational characteristics (shared fail-fast lock, monotonic WikiLog growth, reindex cost, per-space re-bootstrap) must reach self-hosting community operators in user-facing docs, not only the spec.
